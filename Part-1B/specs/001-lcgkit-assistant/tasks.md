# Tasks: lcgkit-assistant

Input: `specs/001-lcgkit-assistant/` (`plan.md`, `spec.md`, `data-model.md`, `research.md`, `quickstart.md`, `contracts/`) and the constitution v1.0.0.

The evaluation harness, the dataset and the tests come before the application (constitution Principles III and V in spirit: the checks must not be written to fit the code). Everything up to the checkpoint is written first and then fixed by the baseline tag; the implementation follows and cannot change it.

## Format

`- [ ] T### [P] [US#] Description with file path`

- `[P]`: the task can run in parallel with others in the same phase (different files, no dependency on an unfinished task).
- `[US#]`: the user story the task belongs to. Setup, harness, dataset, test, foundational and final tasks have no story label.
- `(by me)`: a task I do myself and the coding agent does not.
- Paths are relative to the repository root `Assignment-1/`.

## Rules for every source file

These apply to every task that creates or edits a file under `Part-1B/src/lcgkit_assistant/` or `Part-1B/.harness/`.

- Full type hints and a docstring on every public module, class and function. Each public function's docstring names its task ID and the requirement IDs it covers, for example `Task: T043. Covers: FR-014.`
- Functions of at most 40 lines and complexity of at most 8; split a function rather than suppress a rule.
- No `noqa`, `nosec` or `type: ignore` comments.
- Name every limit and threshold as a constant (for example `MAX_TEXT_LENGTH = 1000`) instead of comparing with literals.
- The API key is read only from `GEMINI_API_KEY`; it is never printed, logged, put in an exception message or written to a file.
- Never edit anything protected by the baseline tag: `tests/`, `evals/`, `specs/` (apart from ticking checkboxes in this file), `.harness/`, `pyproject.toml` and the constitution.
- Every input in a test or in the dataset is synthetic.
